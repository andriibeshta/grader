## Q2 — Ceph vs MinIO, 3 nodes / 50 TB

Must-have facts:
- Ceph: distributed object/block/file; RADOS, CRUSH, OSDs, MON quorum, MGR, RGW for S3; meaningful failure domains need ≥3 nodes; placement groups; self-healing/rebalance; operational complexity; performance depends on OSDs/network.
- MinIO: S3-compatible object store; distributed mode with erasure coding; simple binary/container; erasure sets; S3-only (no block/file); simpler operations; AGPLv3 licensing considerations; good small-cluster fit.
- Both can serve 50 TB on 3 nodes; Ceph is more general but heavier; MinIO is simpler for S3-only.
- Failure modes: Ceph MON quorum loss, OSD failure/rebalance, PG issues; MinIO erasure-set/node loss, heal/rebuild; network bottlenecks.
- Decision criteria: protocols needed, ops maturity, scale/features, licensing/support, expansion.
Common errors: MinIO supports block/file; Ceph is simple; wrong minimum node counts; ignoring licensing/ops.
