## Q3 — pgvector vs Qdrant vs Milvus, 10M embeddings / 50 QPS / hybrid

Must-have facts:
- pgvector: Postgres extension; HNSW/IVFFlat; ACID/SQL; hybrid via full-text/tsvector + vector (or extensions); 10M feasible with tuning; 50 QPS depends on dimension/index/RAM; simplest ops.
- Qdrant: Rust vector DB; HNSW; payload filters; sparse vectors/fusion for hybrid; sharding/replication; REST/gRPC; middle ground.
- Milvus: distributed vector DB; etcd + object storage + message queue (or standalone); multiple index types; high scale; operational complexity; 10M may be overkill; hybrid sparse+dense.
- All three can handle 10M/50 QPS with proper sizing; pgvector simplest, Qdrant balanced, Milvus for larger scale/features.
- Hybrid search changes the choice; pure vector favors pgvector/Qdrant; large-scale/GPU favors Milvus.
Common errors: pgvector cannot do 10M; Qdrant has no hybrid; Milvus is a single binary; ignoring ops burden.
